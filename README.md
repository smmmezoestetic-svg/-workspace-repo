# Mesoforia · Тест по типу кожи

Модуль для страницы https://mesoforia.ru/skin-test/ — пошаговый подбор ухода:
фото → анкета → цели → анализ → персональная рутина и подборка средств.

Собран из прототипа `Skin_Helper_3.html` в вид, пригодный для боевого сайта.

---

## ⚠️ Сначала отзовите старый API-ключ

В прототипе `Skin_Helper_3.html` ключ Anthropic был вписан прямо в HTML —
в строку `window.ANTHROPIC_API_KEY`. Такой ключ виден любому посетителю через
«Просмотр кода страницы», и списания идут с вашего счёта.

**Зайдите в https://console.anthropic.com → API Keys и удалите этот ключ.**
Затем создайте новый — он понадобится на шаге 3 установки и будет храниться только на сервере.

---

## Что изменилось по сравнению с прототипом

| | Прототип | Этот модуль |
|---|---|---|
| Ключ Anthropic | в HTML, виден всем | только на сервере, в PHP-прокси |
| Вес загрузки | ~2.5 МБ (React dev + Babel) | 295 КБ (собранный bundle) |
| JSX | компилировался в браузере при каждом заходе | скомпилирован заранее |
| Панель Tweaks | видна на странице | убрана, настройки вынесены в конфиг |
| Вставка на сайт | отдельная страница целиком | блок в существующую страницу, высота подстраивается |

Отдельно исправлены две вещи, из-за которых виджет ломался бы на боевом сайте:

- **Шрифты Google больше не блокируют запуск.** Обычный `<link rel="stylesheet">`
  на `fonts.googleapis.com` задерживает выполнение скриптов до ответа CDN. У
  российских провайдеров он часто отвечает долго или не отвечает — виджет в
  такой ситуации не отрисовывался вовсе. Теперь шрифты грузятся отдельно, а до
  их приезда работают системные запасные.
- **Убран `min-height: 100vh` у корня приложения.** Внутри iframe, высота
  которого следует за содержимым, это замыкало петлю: блок вырос → вырос и
  `100vh` → уменьшиться уже не может. Короткие шаги занимали высоту самого
  длинного.

## Проверить тест, не трогая сайт

**Запустить локально** — `dist/PROVERIT-LOKALNO.bat` (Windows) или
`dist/PROVERIT-LOKALNO.command` (macOS/Linux) поднимают локальный сервер и
открывают `demo.html`. Работает всё, включая проверку фото. Нужен Python или
Node; скрипт подскажет, если их нет.

Просто открыть `index.html` двойным щелчком нельзя: браузер запрещает
странице, открытой по `file://`, подгружать wasm-детектор.

**Залить папку на хостинг, но не подключать** — скопировать `skin-test-app`
и открыть `/skin-test-app/demo.html`. Страница `/skin-test/` при этом не
трогается.

В `dist/primery-foto/` лежат три снимка — ампула, пейзаж, чашка, — каждый из
которых должен быть отклонён с сообщением «На фото не найдено лицо». Если
хоть один проходит, значит не залита папка `vendor/`.

**Одностраничная версия** — `npm run preview` собирает `dist/preview.html`:
весь тест в одном файле, открывается двойным щелчком и работает с `file://`.
Годится, чтобы показать сценарий и вёрстку или переслать коллегам, но
**проверку фото в ней оценивать нельзя**: детектор в 11 МБ в один файл не
помещается, и там работает урезанная эвристика. Каталог и AI в этом режиме
тоже выключены.

## Установка на 1С-Битрикс

### 1. Залить файлы

Скопируйте содержимое папки `dist/` на хостинг в `/skin-test-app/`.
Через FTP или файловый менеджер Битрикса должно получиться так:

```
/skin-test-app/
    index.html          ← страница виджета (открывается внутри iframe)
    embed.js            ← подключается на странице сайта
    skin-test.js        ← собранное приложение
    skin-test.css
    skin-test.js.map    ← карты исходников, нужны только для отладки
    skin-test.css.map
    demo.html           ← проверочная страница, на боевом сайте не нужна
    vendor/mediapipe/   ← детектор лиц, ~11 МБ, залить целиком
```

Папку `vendor/` пропускать нельзя: в ней лежит детектор лиц, который решает,
есть ли на загруженном фото лицо. Без неё тест начнёт пропускать посторонние
снимки — см. «Проверка фото».

### 2. Вставить блок на страницу

Битрикс → **Сайт → Структура сайта → Файлы и папки → skin-test** → редактировать
страницу → переключиться в режим **HTML** (кнопка «Исходный код») и вставить:

```html
<div data-mesoforia-skin-test data-src="/skin-test-app/index.html"></div>
<script src="/skin-test-app/embed.js" defer></script>
```

Больше на странице ничего не нужно — заголовок и текст вокруг оставьте свои.

### 3. Настроить прокси для AI-анализа

Ключ Anthropic должен лежать на сервере, иначе его заберут из исходников страницы.

**3.1.** Скопируйте `server/proxy.php` и `server/.htaccess` в `/skin-test-app/api/`.

**3.2.** Скопируйте `server/config.sample.php` как `skin-test-config.php` и положите
**на уровень выше корня сайта** — туда, куда веб-сервер не отдаёт файлы напрямую.
Если корень сайта `/var/www/mesoforia/public_html`, то файл кладётся в
`/var/www/mesoforia/skin-test-config.php`.

Если положить выше корня некуда, назовите файл `config.php` и положите рядом с
`proxy.php` — тогда его закроет лежащий там же `.htaccess`. Это менее надёжно:
на nginx без Apache `.htaccess` не работает, и правило нужно прописать в конфиге
сервера вручную.

**3.3.** Впишите в конфиг новый ключ:

```php
'api_key' => 'sk-ant-ваш-новый-ключ',
```

**3.4.** Проверьте, что путь к прокси в `index.html` совпадает с реальным:

```js
apiUrl: "/skin-test-app/api/proxy.php"
```

Если AI-анализ не нужен вообще — оставьте `apiUrl: ""`. Тест продолжит работать
на анкете и локальном разборе фото, только без Vision-AI, и ключ не понадобится.

### 4. Проверить

Откройте `https://mesoforia.ru/skin-test-app/demo.html` — там виджет показан
внутри макета обычной страницы. Пройдите тест до результата. Если всё в порядке,
`demo.html` можно удалить с хостинга.

## Настройки

Задаются в `dist/index.html` в объекте `window.MESOFORIA_SKIN_TEST_CONFIG`:

| Параметр | Значения | По умолчанию | Что делает |
|---|---|---|---|
| `lang` | `ru`, `en` | `ru` | Язык интерфейса |
| `embed` | `full`, `widget` | `full` | `full` — во всю ширину блока, `widget` — карточка 480 px по центру |
| `accent` | `rose`, `sage`, `graphite`, `amber`, `blush` | `rose` | Акцентный цвет |
| `fontScale` | 0.85–1.25 | `1` | Масштаб шрифта |
| `shopUrl` | URL | `https://mesoforia.ru/` | Куда ведут кнопки «в магазин» |
| `apiUrl` | путь к прокси | — | Пусто — AI-анализ выключен |
| `catalogUrl` | путь к каталогу | — | Пусто — демо-каталог из сборки |
| `addToCartUrl` | путь к эндпоинту | — | Пусто — вместо кнопки «в корзину» ссылка в магазин |
| `cartPageUrl` | URL | `/personal/cart/` | Куда вести после добавления |

Те же параметры можно задать прямо в блоке на странице, не трогая `index.html`:

```html
<div data-mesoforia-skin-test
     data-src="/skin-test-app/index.html"
     data-lang="en"
     data-accent="sage"></div>
```

### Настройки прокси

В `skin-test-config.php`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `allowed_origins` | mesoforia.ru | Домены, которым разрешено обращаться к прокси |
| `model` | `claude-haiku-4-5-20251001` | Модель. Задаётся на сервере — клиент её не выбирает |

## Проверка фото

Перед анализом тест убеждается, что на снимке действительно лицо. Этим
занимается MediaPipe Face Mesh — та же библиотека, которая потом размечает
зоны лица.

Её файлы лежат в `public/vendor/mediapipe/` и заливаются вместе с виджетом,
а не подгружаются с внешнего CDN. Причина простая: если библиотека не
загрузилась, проверять лицо нечем, и тест вынужден полагаться на эвристику по
цвету пикселей — а она пропускает чашку кофе и отклоняет черно-белый портрет.
Собственный домен отвечает всегда.

Вес тот же, что и раньше с CDN (~10 МБ, один раз, дальше из кэша браузера) —
изменилась только надёжность. Заодно перестал деградировать и сам анализ:
раньше при недоступном CDN результат показывался как `PROFILE-ONLY` с
точностью 60%, теперь считается по зонам лица.

В папке лежит сборка с поддержкой WebAssembly SIMD — Chrome 91+, Firefox 89+,
Safari 16.4+. Более старые браузеры определяются автоматически и уходят на
CDN, как раньше.

Проверяется и загруженный файл, и снимок с камеры. Демо-фото проверку не
проходит: это рисунок, лица там нет по определению.

## Каталог средств

По умолчанию тест использует демо-каталог, зашитый в `src/02-data.jsx`. Это
выдуманные средства и цены — для боевого сайта нужно подключить настоящий
каталог. Есть два способа, оба задаются параметром `catalogUrl`.

Когда `catalogUrl` задан, демо-каталог **не** используется как запасной
вариант: если каталог не загрузился, тест покажет анализ кожи и уведомление
«подборка средств временно недоступна». Показать покупателю выдуманные
средства с выдуманными ценами хуже, чем честно сказать о сбое.

### Способ 1 — товары из Битрикса (рекомендуемый)

Состав подбора управляется галочкой в карточке товара: поставили — товар
участвует в тесте, сняли — исчез. Цены, фото и ссылки берутся из самой
карточки, поэтому разойтись с магазином им негде.

**1. Завести свойства в инфоблоке.** Контент → Инфоблоки → Типы инфоблоков →
ваш каталог → Свойства:

| Название | Код | Тип | Множ. | Обязательно |
|---|---|---|---|---|
| Участвует в тесте | `USE_IN_SKIN_TEST` | Список (одно значение `Y`) или Да/Нет | нет | да |
| Категория средства | `SKIN_TEST_CATEGORY` | Список | нет | да |
| Для типов кожи | `SKIN_TEST_TYPES` | Список | **да** | да |
| Решает задачи | `SKIN_TEST_GOALS` | Список | **да** | нет |
| Активные компоненты | `SKIN_TEST_ACTIVES` | Строка | **да** | нет |

Значения списков (в скобках — внутренний ключ, который тест понимает):

- **Категория:** Очищение (`cleanser`), Тонер (`toner`), Сыворотка (`serum`),
  Крем для век (`eye`), Крем (`moist`), SPF (`spf`), Маска (`mask`),
  Эксфолиант (`exfoliant`).
- **Типы кожи:** Нормальная (`normal`), Сухая (`dry`), Жирная (`oily`),
  Комбинированная (`combo`), Чувствительная (`sensitive`), Склонная к акне
  (`acne`), Возрастная (`mature`), Обезвоженная (`dehydrated`).
- **Задачи:** Увлажнение (`hydration`), Anti-age (`antiage`), Пигментация
  (`pigment`), Акне (`acne`), Поры (`pores`), Купероз (`redness`), Сияние
  (`glow`), Зона глаз (`eyes`).

Надёжнее всего при создании значения списка проставить ему **XML_ID** равным
внутреннему ключу — тогда переименование значения в админке ничего не сломает.
Если XML_ID не проставлен, сработает сопоставление по названию: таблицы
соответствий лежат в `catalog-config.php` в секции `value_maps`, туда же можно
дописать свои формулировки.

Шаг рутины (утро, вечер, еженедельно) выводится из категории — отдельное
свойство заводить не нужно.

**2. Поставить файлы.** `server/catalog.php` и `server/catalog-helpers.php` —
в `/skin-test-app/api/`. `server/catalog-config.sample.php` — туда же под
именем `catalog-config.php`, и указать в нём `iblock_id` вашего каталога.

**3. Включить в виджете:**

```js
catalogUrl: "/skin-test-app/api/catalog.php"
```

Что `catalog.php` делает сам: отдаёт только активные товары с проставленной
галочкой, прячет отсутствующие в наличии (если включён складской учёт),
берёт базовую цену из «Торгового каталога», кэширует готовый ответ на 10 минут
и пропускает товары без категории, цены или типов кожи, чтобы они не ломали
подбор.

### Способ 2 — список из файла

Если каталог пока проще вести руками или выгружать из Excel, положите
`products.json` рядом с виджетом и укажите:

```js
catalogUrl: "/skin-test-app/products.json"
```

Формат — `server/products.sample.json`, там же лежит рабочий пример:

```json
{
  "version": 1,
  "products": [
    {
      "id": "12345",
      "category": "serum",
      "name": { "ru": "Сыворотка «Ниацинамид 10»" },
      "price": 4890,
      "volume": "30 мл",
      "actives": ["Ниацинамид 10%", "Цинк"],
      "types": ["oily", "combo", "acne"],
      "goals": ["pores", "pigment", "acne"],
      "url": "/catalog/serum/niacinamide-10/",
      "image": "/upload/iblock/ab/niacinamide.jpg"
    }
  ]
}
```

Обязательны `category`, `name`, `price` и непустой `types` — без них товар
пропускается. `url` и `image` необязательны: со ссылкой название на карточке
станет кликабельным, с картинкой вместо схематичного флакона покажется фото.

Формат у обоих способов одинаковый, поэтому переезд с файла на Битрикс —
это смена одной строки `catalogUrl`, виджет переделывать не нужно.

## Добавление в корзину

На итоговом экране кнопка «Добавить в корзину» кладёт все отобранные средства
в корзину сайта одним нажатием, после чего появляется ссылка на корзину.
Пока `addToCartUrl` пуст, там по-прежнему просто ссылка в магазин.

**1.** Скопируйте `server/add-to-cart.php` в `/skin-test-app/api/` — он берёт
настройки из того же `catalog-config.php`, что и выгрузка каталога.

**2.** Включите в виджете:

```js
addToCartUrl: "/skin-test-app/api/add-to-cart.php",
cartPageUrl:  "/personal/cart/"
```

Запрос уходит на тот же домен, поэтому сессионная кука магазина
прикладывается браузером сама и товары попадают в корзину именно этого
посетителя. Класть можно только активные товары нужного инфоблока с
проставленной галочкой «участвует в тесте» — эндпоинт не должен превращаться
в способ добавить в корзину что угодно по чужой наводке.

**Товары с торговыми предложениями.** У такого товара покупается не он сам,
а предложение, поэтому `add-to-cart.php` берёт первое активное предложение.
Если у вас несколько предложений на товар и нужно другое правило выбора —
по цене, по остатку, по объёму — меняется это в функции `resolveBuyableId`.
Проверьте этот момент первым: он зависит от того, как устроен ваш каталог.

Если часть позиций положить не удалось, тест сообщит об этом и добавит
остальные. Причина по каждой позиции возвращается в поле `skipped`
(`not-allowed` — нет галочки или товар неактивен, `no-offer` — не нашлось
торгового предложения, `add-failed` — Битрикс отказал; подробности в логе
сервера).

### Проверка

Откройте консоль браузера (F12) на странице с тестом. Загрузчик пишет туда,
сколько товаров он отбросил и в каких категориях не осталось ни одного —
пустая категория означает, что соответствующий шаг просто выпадет из рутины.

## Что делает прокси

Браузер отправляет на `proxy.php` только массив `messages`. Прокси:

- проверяет `Origin` по списку разрешённых доменов;
- считает запросы по IP в скользящем часовом окне;
- пропускает только ту форму сообщений, которую шлёт виджет — роли `user` и
  `assistant`, блоки `text` и `image` с base64-картинкой разрешённого типа;
- подставляет модель и `max_tokens` сам, поэтому подделанный запрос не сможет
  ни сменить модель, ни выкрутить лимит токенов;
- на ошибку от Anthropic отдаёт наружу общую формулировку, а подробности пишет
  в лог сервера — тексты ошибок API могут содержать детали ключа и биллинга.

## Разработка

```bash
npm install
npm run build      # production-сборка в dist/
npm run dev        # пересборка при изменениях
npm run check      # сборка без минификации, читаемый вывод
```

Структура исходников:

```
src/
    index.jsx         точка входа: порядок подключения модулей и монтирование
    config.js         настройки (по умолчанию → window-объект → query-параметры)
    embed-host.js     передача высоты родительской странице через postMessage
    styles.css        дизайн-система и все стили
    01-i18n.jsx       строки ru/en
    02-data.jsx       типы кожи, зоны лица, каталог средств и процедур
    03-analyzer.jsx   MediaPipe Face Mesh + Vision-AI через прокси
    04-shared.jsx     общие элементы интерфейса
    05-photo.jsx      шаг с фото и проверка кадра
    06-profile.jsx    анкета, цели, бюджет
    07-scan.jsx       экран анализа
    08-result.jsx     результат: карта проблем, рутина, подборка
    09-analog.jsx     подбор аналога по фото средства
    10-app.jsx        корневой компонент и маршрутизация по шагам
```

Модули подключаются строго по порядку — каждый регистрирует компоненты в
`window.*`, а следующие на них опираются. Порядок задан в `src/index.jsx`.

## Ограничения

- **Запасная эвристика проверки фото — слабая.** Она включается, только если
  MediaPipe не загрузился ни локально, ни с CDN, либо не ответил за 8 секунд.
  Отклонять фото в этой ситуации нельзя (иначе сбой закроет тест всем), а
  отличить кожу от предмета телесного цвета по пикселям надёжно невозможно.
  Проверьте, что папка `vendor/` залита на хостинг — тогда этот путь не
  задействуется.
- **Демо-каталог в `src/02-data.jsx` — выдуманные средства и цены.** На боевом
  сайте нужно подключить настоящий каталог, см. раздел «Каталог средств».
- **`catalog.php` и `add-to-cart.php` не проверены на живом Битриксе** — в окружении, где он писался,
  Битрикса нет. Разбор значений свойств покрыт тестом
  (`php server/tests/catalog-helpers.test.php`), но выборку из инфоблока,
  цены и остатки нужно проверить на самом сайте: откройте
  `/skin-test-app/api/catalog.php` в браузере и посмотрите, что в JSON попали
  ожидаемые товары. Для корзины отдельно проверьте товары с торговыми
  предложениями — правило выбора предложения зависит от вашего каталога.
- **Салонные процедуры остаются в коде** (`src/02-data.jsx`, `PROCEDURES`) —
  на сайте их нет как отдельных элементов, поэтому из каталога они не тянутся.
