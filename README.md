# Mesoforia · Тест по типу кожи

Модуль для страницы https://mesoforia.ru/skin-test/ — пошаговый подбор ухода:
фото → анкета → цели → анализ → персональная рутина и подборка средств.

Собран из прототипа `Skin_Helper_3.html` в вид, пригодный для боевого сайта.

---

## ⚠️ Сначала отзовите старый API-ключ

В прототипе `Skin_Helper_3.html` ключ Anthropic был вписан прямо в HTML —
в строку `window.ANTHROPIC_API_KEY`. Такой ключ виден любому посетителю через
«Просмотр кода страницы», и списания идут с вашего счёта.

**Зайдите в https://console.anthropic.com → API Keys и удалите этот ключ.**
Затем создайте новый — он понадобится на шаге 3 установки и будет храниться только на сервере.

---

## Что изменилось по сравнению с прототипом

| | Прототип | Этот модуль |
|---|---|---|
| Ключ Anthropic | в HTML, виден всем | только на сервере, в PHP-прокси |
| Вес загрузки | ~2.5 МБ (React dev + Babel) | 295 КБ (собранный bundle) |
| JSX | компилировался в браузере при каждом заходе | скомпилирован заранее |
| Панель Tweaks | видна на странице | убрана, настройки вынесены в конфиг |
| Вставка на сайт | отдельная страница целиком | блок в существующую страницу, высота подстраивается |

Отдельно исправлены две вещи, из-за которых виджет ломался бы на боевом сайте:

- **Шрифты Google больше не блокируют запуск.** Обычный `<link rel="stylesheet">`
  на `fonts.googleapis.com` задерживает выполнение скриптов до ответа CDN. У
  российских провайдеров он часто отвечает долго или не отвечает — виджет в
  такой ситуации не отрисовывался вовсе. Теперь шрифты грузятся отдельно, а до
  их приезда работают системные запасные.
- **Убран `min-height: 100vh` у корня приложения.** Внутри iframe, высота
  которого следует за содержимым, это замыкало петлю: блок вырос → вырос и
  `100vh` → уменьшиться уже не может. Короткие шаги занимали высоту самого
  длинного.

## Установка на 1С-Битрикс

### 1. Залить файлы

Скопируйте содержимое папки `dist/` на хостинг в `/skin-test-app/`.
Через FTP или файловый менеджер Битрикса должно получиться так:

```
/skin-test-app/
    index.html          ← страница виджета (открывается внутри iframe)
    embed.js            ← подключается на странице сайта
    skin-test.js        ← собранное приложение
    skin-test.css
    skin-test.js.map    ← карты исходников, нужны только для отладки
    skin-test.css.map
    demo.html           ← проверочная страница, на боевом сайте не нужна
```

### 2. Вставить блок на страницу

Битрикс → **Сайт → Структура сайта → Файлы и папки → skin-test** → редактировать
страницу → переключиться в режим **HTML** (кнопка «Исходный код») и вставить:

```html
<div data-mesoforia-skin-test data-src="/skin-test-app/index.html"></div>
<script src="/skin-test-app/embed.js" defer></script>
```

Больше на странице ничего не нужно — заголовок и текст вокруг оставьте свои.

### 3. Настроить прокси для AI-анализа

Ключ Anthropic должен лежать на сервере, иначе его заберут из исходников страницы.

**3.1.** Скопируйте `server/proxy.php` и `server/.htaccess` в `/skin-test-app/api/`.

**3.2.** Скопируйте `server/config.sample.php` как `skin-test-config.php` и положите
**на уровень выше корня сайта** — туда, куда веб-сервер не отдаёт файлы напрямую.
Если корень сайта `/var/www/mesoforia/public_html`, то файл кладётся в
`/var/www/mesoforia/skin-test-config.php`.

Если положить выше корня некуда, назовите файл `config.php` и положите рядом с
`proxy.php` — тогда его закроет лежащий там же `.htaccess`. Это менее надёжно:
на nginx без Apache `.htaccess` не работает, и правило нужно прописать в конфиге
сервера вручную.

**3.3.** Впишите в конфиг новый ключ:

```php
'api_key' => 'sk-ant-ваш-новый-ключ',
```

**3.4.** Проверьте, что путь к прокси в `index.html` совпадает с реальным:

```js
apiUrl: "/skin-test-app/api/proxy.php"
```

Если AI-анализ не нужен вообще — оставьте `apiUrl: ""`. Тест продолжит работать
на анкете и локальном разборе фото, только без Vision-AI, и ключ не понадобится.

### 4. Проверить

Откройте `https://mesoforia.ru/skin-test-app/demo.html` — там виджет показан
внутри макета обычной страницы. Пройдите тест до результата. Если всё в порядке,
`demo.html` можно удалить с хостинга.

## Настройки

Задаются в `dist/index.html` в объекте `window.MESOFORIA_SKIN_TEST_CONFIG`:

| Параметр | Значения | По умолчанию | Что делает |
|---|---|---|---|
| `lang` | `ru`, `en` | `ru` | Язык интерфейса |
| `embed` | `full`, `widget` | `full` | `full` — во всю ширину блока, `widget` — карточка 480 px по центру |
| `accent` | `rose`, `sage`, `graphite`, `amber`, `blush` | `rose` | Акцентный цвет |
| `fontScale` | 0.85–1.25 | `1` | Масштаб шрифта |
| `shopUrl` | URL | `https://mesoforia.ru/` | Куда ведут кнопки «в магазин» |
| `apiUrl` | путь к прокси | — | Пусто — AI-анализ выключен |

Те же параметры можно задать прямо в блоке на странице, не трогая `index.html`:

```html
<div data-mesoforia-skin-test
     data-src="/skin-test-app/index.html"
     data-lang="en"
     data-accent="sage"></div>
```

### Настройки прокси

В `skin-test-config.php`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `allowed_origins` | mesoforia.ru | Домены, которым разрешено обращаться к прокси |
| `model` | `claude-haiku-4-5-20251001` | Модель. Задаётся на сервере — клиент её не выбирает |
| `max_tokens` | 1024 | Потолок длины ответа |
| `rate_limit_per_hour` | 60 | Запросов с одного IP в час; `0` — без лимита |
| `max_body_bytes` | 8 МБ | Потолок размера запроса вместе с фото |

---

## Что делает прокси

Браузер отправляет на `proxy.php` только массив `messages`. Прокси:

- проверяет `Origin` по списку разрешённых доменов;
- считает запросы по IP в скользящем часовом окне;
- пропускает только ту форму сообщений, которую шлёт виджет — роли `user` и
  `assistant`, блоки `text` и `image` с base64-картинкой разрешённого типа;
- подставляет модель и `max_tokens` сам, поэтому подделанный запрос не сможет
  ни сменить модель, ни выкрутить лимит токенов;
- на ошибку от Anthropic отдаёт наружу общую формулировку, а подробности пишет
  в лог сервера — тексты ошибок API могут содержать детали ключа и биллинга.

## Разработка

```bash
npm install
npm run build      # production-сборка в dist/
npm run dev        # пересборка при изменениях
npm run check      # сборка без минификации, читаемый вывод
```

Структура исходников:

```
src/
    index.jsx         точка входа: порядок подключения модулей и монтирование
    config.js         настройки (по умолчанию → window-объект → query-параметры)
    embed-host.js     передача высоты родительской странице через postMessage
    styles.css        дизайн-система и все стили
    01-i18n.jsx       строки ru/en
    02-data.jsx       типы кожи, зоны лица, каталог средств и процедур
    03-analyzer.jsx   MediaPipe Face Mesh + Vision-AI через прокси
    04-shared.jsx     общие элементы интерфейса
    05-photo.jsx      шаг с фото и проверка кадра
    06-profile.jsx    анкета, цели, бюджет
    07-scan.jsx       экран анализа
    08-result.jsx     результат: карта проблем, рутина, подборка
    09-analog.jsx     подбор аналога по фото средства
    10-app.jsx        корневой компонент и маршрутизация по шагам
```

Модули подключаются строго по порядку — каждый регистрирует компоненты в
`window.*`, а следующие на них опираются. Порядок задан в `src/index.jsx`.

## Ограничения

- **MediaPipe Face Mesh грузится с внешнего CDN** (`cdn.jsdelivr.net`,
  запасной — `unpkg.com`). Если оба недоступны, разбор фото по зонам
  пропускается: тест переходит на анкету, а точность в результате
  показывается как `PROFILE-ONLY` — это штатное поведение, не ошибка.
- **Каталог средств зашит в `src/02-data.jsx`** — это данные из прототипа, они
  не связаны с реальным каталогом магазина. Перед запуском их нужно сверить с
  ассортиментом и ценами, иначе тест будет советовать то, чего нет в продаже.
- **Результат теста не является медицинской рекомендацией.** Стоит добавить
  соответствующую оговорку на странице рядом с блоком.
- **Фото уходит на серверы Anthropic** при включённом Vision-AI. Это
  персональные данные — нужно упоминание в политике конфиденциальности и
  согласие пользователя перед загрузкой фото.
